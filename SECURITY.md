# Security Policy

## Our Commitment

Security and privacy are core principles of Chitti.

Chitti is designed to handle sensitive financial information responsibly, with a focus on secure engineering practices, data protection, and transparency.

---

# Supported Versions

Security updates will be provided for actively maintained versions.

| Version | Supported |
|---------|-----------|
| Latest release | ✅ |
| Previous release | ⚠️ |
| Older versions | ❌ |

---

# Reporting a Vulnerability

Please do not publicly disclose security vulnerabilities through GitHub Issues.

If you discover a security issue, please report it privately with:

- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Screenshots or logs (if applicable)
- Suggested fix (optional)

---

# Security Review Process

Reported vulnerabilities will be reviewed based on:

- Severity
- User impact
- Data exposure risk
- Exploitability

We aim to:

1. Acknowledge reports
2. Investigate the issue
3. Develop a fix
4. Release security updates
5. Publish appropriate disclosure notes

---

# Security Principles

Chitti follows:

- Secure by design architecture
- Least privilege access
- Strong authentication
- Data encryption
- Secure API practices
- Audit logging
- Regular dependency updates

---

# Responsible Disclosure

We appreciate security researchers and contributors who help improve Chitti.

Security improvements benefit the entire community.

Thank you for helping keep Chitti secure.
